# 需求澄清与用户决策门

开工卡以 SKILL.md 为准。源码能唯一决定的事实直接填写；只有缺失选择会改变用户可见结果、公开 contract 或修改范围时才询问。

## 必须停下的多解

- accountMode 会改变登录、token/header、请求/DTO、cache、UI 或 reset；
- 交互、排序、默认值、文案或验收结果有多个合理口径；
- API 字段、null/清空语义、错误码、写操作或权限未定义；
- 真实图片/动画/品牌/语言素材缺失；
- 平台能力缺失后的隐藏、禁用、提示或替代流程未决定；
- owner、公开 API、状态身份、route contract 或设备页面范围不明；
- 方案会新增依赖、改变公开行为或触碰任务外文件。

不得用个人分支、第一处搜索结果、通用最佳实践、临时素材或自创接口补空白。

## 设备页面

改变设备分流、共享详情行为或服务规则且叶子范围会改变实现时，枚举 deviceType、scene/category、cameraScene、账号/服务/分享状态、route、最终 Page 和点击区域。存在多个独立叶子且范围未说明时，只问“覆盖全部还是指定叶子”，确认前不写代码；仅修改用户指定局部控件且不改变分流、共享契约或其他叶子行为时，可按明确范围实施，无需追加全设备询问。

## 停止格式

聚焦调查 owner、调用方/测试及必要同类样本后，若相关账号/API/route/资源/平台仍存在会改变用户结果的多解，返回：

    已确认：<源码事实>
    待决定：<一个问题>
    方案差异：<对行为、账号、素材、范围或平台的影响>
    建议：<有证据时>

私有命名、等价控制流等不改变公开行为、owner、生命周期或范围的细节，可沿目标 owner 的成熟样本自行决定。
