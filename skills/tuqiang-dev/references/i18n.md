# 国际化规范（core_i18n）

途强不用 intl ARB 或 getx，使用 `core_i18n` 加载 9 个 JSON。中文原文是稳定 key，其他语言文件使用同一个 key 映射到译文。

## 1. 代码写法

```dart
import 'package:core_i18n/core_i18n.dart';

Text('选择品种'.tr);
'绑定{key}成功'.keyTr('旺财');
'共{count}只{type}'.multiKeyTr({'count': '3', 'type': '猫'});
```

`keyTr(value)` 只替换字面占位符 `{key}`；需要 `{name}`、`{count}` 等自定义命名占位符时使用 `multiKeyTr({...})`，不要把二者混用。

需要翻译的是代码写死的用户可见文案，包括页面标题、按钮、Toast、弹窗和权限说明。后端返回且已经按服务端协议本地化的文案、日志、调试文本、测试 fixture 和非用户可见数据不要机械套 `.tr`。

不要在 Widget/State 成员中用 `final` 或 `static final` 缓存 `.tr` 结果；语言切换后这些值不会自动重新求值。使用 build 内表达式或 getter。

## 2. 新增文案

资源位于 `apps/tuqiang_app/assets/i18n/`：

```text
manifest.json
zh_CN.json  en_US.json  ar.json  de.json  es.json
fr.json     id.json     it.json  vi.json
```

例如：

```json
// zh_CN.json
"洗澡记录": "洗澡记录"
// en_US.json
"洗澡记录": "Bath Records"
```

步骤：

1. 在 `zh_CN.json` 添加中文 key/value；
2. 在其余 8 个 JSON 使用相同 key 添加译文；
3. 保持 JSON 为非空字符串键和值，不能改 manifest schema 或 fallback；
4. 不需要新增 Dart 注册代码，loader 按 manifest 加载。

不要混淆项目中的三套语言标识：

| 用途 | 中文 | 英文 | 其余语言 |
|---|---|---|---|
| 资源 manifest / 字典 key | `zh_CN` | `en_US` | `ar/de/es/fr/id/it/vi` |
| `TQLanguageType.name` / `MaterialApp Locale` | `zh` | `en` | `ar/de/es/fr/id/it/vi` |
| `TQLanguageType.languageCode`、本地持久化及后端历史协议 | `zh-CN` | `en-US` | `ar/de/es/fr/id/it/vi` |

资源 fallback 为 `en_US`。新增语言或传参时先确认目标 API 需要哪一套标识，不能把 `zh_CN`、`zh` 与 `zh-CN` 互换。阿拉伯语还要检查 RTL 布局。

## 3. 语言切换与清理 owner

语言切换不是一个 owner 包办全部职责，按三层处理：

| Owner | 负责什么 | 不负责什么 |
|---|---|---|
| `core_i18n` / `TQI18nManager` | 当前语言、字典加载、持久化及 `.tr` 等翻译 API | 不知道设备、广告、GPS 等业务缓存，也不聚合 Feature |
| 具体 Feature 或 `shared_business` 子域 | 清理自己拥有的语言派生缓存，并通过公开 primitive、resetter 或 participant 暴露能力 | 不直接清理其他 Feature，不自行编排全局语言切换 |
| `apps/tuqiang_app/lib/app/session/LanguageChangeCoordinator` | 在 App composition 层聚合各 owner 的清理入口并控制执行顺序 | 不承载具体 Feature 的缓存实现 |

Feature 禁止的是另起一套全局语言状态/切换流程，或直接越界操作其他 Feature；它可以且应当拥有自身缓存的清理实现。新增跨 Feature 清理时，先把 primitive 放回真实业务 owner，再由 App coordinator 注入、注册或调用。不要把业务缓存下沉到 `core_i18n`，也不要因为多个 Feature 都参与清理就把具体实现统统塞入 `shared_business`。

## 4. 验证

- 检查 9 个 JSON 的 key 集合和 JSON 语法；
- 切换中文、英文、阿拉伯语检查新页面；
- 修改 manifest、loader 或公共 i18n 代码时运行 boundary、standard/OHOS analyze 和对应测试；
- 普通新增文案至少检查 diff 和运行时加载，不需要为了每次文案修改运行完整构建。
