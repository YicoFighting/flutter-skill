# Tuqiang 国际化

标题、按钮、标签、Toast、Dialog、空态、错误、权限用途、tooltip、semanticLabel 和图片语言变体都触发本流程；日志、注释、协议值和后端已本地化内容不机械翻译。

## 事实源

- apps/tuqiang_app/assets/i18n/manifest.json：当前 locale 与 fallback 的唯一清单；每次读取，不把文档中的语言列表当常量。
- 同目录 JSON：Tuqiang 文案。
- packages/core/core_i18n：TQLanguageType、TQI18nManager 与 tr/keyTr/multiKeyTr。
- apps/tuqiang_app 的 LanguageChangeCoordinator：语言缓存清理；具体缓存仍归各 owner。

区分 translation locale（如 zh_CN）、Flutter Locale（zh）和持久化/协议代码（zh-CN）。

## 修改规则

1. 先按业务语义复用已有 key；没有合适 key 才新增，并同步 manifest 当前列出的全部 locale，值必须是非空字符串。
2. 全部语言只允许 {identifier} 占位符且集合一致；{ count}、嵌套或未配对花括号均错误。keyTr 只用于 {key}，具名参数使用 multiKeyTr。
3. 普通产品文案标明翻译来源或待语言复核；法律、隐私、付费、安全或多义文案必须取得正式译文。
4. Arabic 同时检查 RTL、对齐、方向性图标、数字/单位和溢出；图片文案使用真实语言 asset。

    Text('选择品种'.tr);
    '绑定{key}成功'.keyTr(name);
    '共{count}只{type}'.multiKeyTr({'count': count, 'type': type});

## 两个隐蔽缺陷

TQI18nManager 按“当前语言 → fallback → 原始 key”查找，所以调用 .tr 不证明 key 存在；literal source key 必须在全部当前 locale 中出现。

禁止在顶层、static/final、singleton、Repository/Model cache 或其他长生命周期 owner 保存已翻译结果。应在 getter、build 或使用时动态求值，否则切语言后仍显示旧值。

语言切换有登录前 Auth 与登录后 Mine 两个入口。修改加载、持久化或清理时，两边都追到：

    ensureLanguageLoaded → setLanguage → clearLanguageCache → Phoenix.rebirth

## 验证

对本次每个复用或新增 source key 显式传入 --key；脚本也自动发现变更 locale key 和变更 Dart literal 调用：

    python -X utf8 <TUQIANG_DEV_SKILL>/scripts/validate_tuqiang_i18n.py --root <TUQIANG_ROOT> --key '<source key>'

脚本严格检查 manifest/locale JSON、重复/空 key、非字符串/空值、全 locale 覆盖、合法占位符和调用参数；删除 key 后仍有 literal 调用会失败。multiKeyTr 的变量 Map、spread、computed key、collection-if/for 无法静态证明，会 fail-closed。

脚本不判断翻译语义、所有未加 .tr 的可见硬编码、动态生成 key、RTL 或布局；这些仍需 diff、Widget 和真机/截图检查。测试与 analyze 命令统一见 [testing.md](testing.md)；现有 loader/boundary 测试不能单独替代本检查。
