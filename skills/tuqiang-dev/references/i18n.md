# Tuqiang 国际化与展示取值

标题、按钮、Toast、Dialog、空态、错误、权限用途、tooltip、semanticLabel 与图片语言变体触发本流程；日志、协议值、用户输入和后端已本地化内容不机械翻译。原生侧（Android/iOS/鸿蒙）使用各自平台资源，不用 `.tr` 替代。

## 先确认值的契约

| 输入 | 处理 |
|---|---|
| 本地 source key | 在展示边界调用一次 `.tr` / `keyTr` / `multiKeyTr` |
| 已翻译的 getter / label | 直接展示，不再 `.tr`、不反查 key、不按译文判断业务状态 |
| 后端业务数据、用户输入 | 按字段契约展示，名称、地址、接口消息等动态内容不当 key |
| code / enum | 复用已有映射；业务判断用 code/enum，展示用其 UI getter |

先读已有 getter/组件的实现与调用处，例如 `BeaconTypeUi.displayName`、`TQClientTypeUi.displayName` 已翻译。旧字段、空值或格式兼容在现有 Model/adapter/展示 owner 中按已确认协议处理一次，下游消费同一结果；没有协议证据不加兼容分支。不同层真实存在的缺失状态（如 Model 本身为空）仍可处理。

## fallback 只归国际化基础层

- 资源覆盖以 `apps/tuqiang_app/assets/i18n/manifest.json` 的全部 locale 为准（当前 9 个）；`TQI18nManager.supportLangList` 只是可选语言列表（zh/en），不能推导覆盖范围。
- `core_i18n/lib/src/tq_i18n_manager.dart::getText` 已执行"当前 locale → manifest fallback（en_US）→ 原始 key"，只对缺键（null）回退，空字符串不回退。
- 因此不新增页面级 `safeTr`/`trOrDefault`、中英判断、第二套查表或 `translated == key` 兜底；缺译应修复资源，`.tr` 有返回值不代表已覆盖。
- 业务空态/缺值占位与翻译缺失是不同契约：先在 owner 按数据规则取值，确需产品占位时用已有或补齐的 source key，再翻译一次。

## 文案修改

1. 按语义复用已有 key；新增 key 或改占位符时同步 manifest 全部 locale，值为非空字符串。
2. 只用 `{identifier}` 占位符且各语言集合一致；`keyTr` 只替换 `{key}`，具名参数用 `multiKeyTr`（值为 `String`），不靠拼接整句迁就语序。
3. 普通译文注明来源或待复核；法律、隐私、付费、安全与多义文案需要正式译文。范围可达 Arabic 等 RTL 时检查方向性图标、数字/单位与溢出；图片文案用真实语言 asset。

```dart
Text('选择品种'.tr);
'绑定{key}成功'.keyTr(name);
'共{count}只{type}'.multiKeyTr({'count': count.toString(), 'type': type});
```

不在顶层、static/final、singleton、Repository/Model cache 等长生命周期 owner 保存译文（项目规范：含中文字符串的变量不用 `final`）；在 getter、build 或实际展示时读取。`.tr` 依赖全局语言，本身不是纯函数。

## 加载与切换

`AppI18nRepository.installStartupTranslations` 启动加载当前语言、中英与 fallback，其他语言经 `ensureLanguageLoaded` 按需合并。区分 translation locale（`zh_CN`）、Flutter Locale（`zh`）与持久化/协议代码（`zh-CN`），复用 `TQLanguageType` 转换。

改动加载、持久化或缓存时同时检查 `feature_auth/lib/src/page/lang_change_page.dart` 与 `feature_mine/lib/setting/setting_page.dart`：`prepareLanguage → ensureLanguageLoaded → setLanguage → clearLanguageCache → Phoenix.rebirth`。保持"加载成功、mounted 检查后再切换"的顺序；`LanguageChangeCoordinator` 清语言相关状态，各缓存仍归原 owner。

## 验证

对本次复用或新增的每个 source key 显式传 `--key`；脚本也会自动发现变更的 locale key 与 Dart literal 调用（只读，不跑 Flutter）：

```text
python -X utf8 <TUQIANG_DEV_SKILL>/scripts/validate_tuqiang_i18n.py --root <TUQIANG_ROOT> --key '<source key>'
```

脚本检查 JSON、重复/空 key、非字符串/空值、全 locale 覆盖、占位符与调用参数；删除 key 后仍有 literal 调用会失败，变量 Map、spread、computed key、collection-if/for 无法静态证明时 fail-closed。它不证明翻译语义、动态 key、可见硬编码、RTL 或布局：沿展示链确认"原始值 → 唯一取值 owner → 展示"没有重复兼容或翻译，切语言改动再验证现有页面与相关缓存。
