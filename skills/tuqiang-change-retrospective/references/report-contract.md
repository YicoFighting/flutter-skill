# Markdown 输出约定

生成一份脱离聊天上下文也能理解的 Markdown。只写复盘文档，不因此获得修改业务代码、测试、配置或 Git 的权限。

## 文件

路径优先级：用户文件 → 用户目录 → 项目规范 → docs/learning。默认名为 `YYYY-MM-DD-{bug|feature|hybrid}-<safe-kebab-slug>.md`。

除非用户明确要求更新原文，不覆盖已有文件，重名时加 `-2`、`-3`。使用 UTF-8 无 BOM，末尾换行。

## 内容随问题裁剪

每份文档说明复盘对象/范围、结果、关键原因或实现、证据与实际验证状态。这些可写为短段落，不要求固定标题或表格。分支/HEAD、未提交状态、账号/平台只记录足以辨认本次改动的相关信息。

- 简单 Bug：症状与期望 → 原因 → 修复前后 → 验证与缺口。
- 简单需求：目标与验收 → 关键实现及复用 → 完成程度与验证。
- 复杂改动：按需要补充跨文件链、时序、输入输出、重要取舍或历史因果。
- 混合改动：以需求为主线，在相关实现处说明 Bug；仍只输出一份文档。

没有关联或证据的栏目直接省略，不为凑模板填写“不适用”。不强制因果金字塔、三条泳道、全量矩阵、证据账本或学习总结；仅在确实帮助理解时使用。

## 证据和完成检查

- 当前代码使用仓库相对路径与实时 1-based 行号；历史代码使用 `path@short-sha`。摘录只保留证明关键变化所需的源码。
- 已证实事实、推断与未知清楚区分。涉及 Git 归因时按 [Git 因果](git-causality.md) 标注角色与置信度。
- 用户确认、已有测试/静态检查、真机或集成结果分别说明；没有执行的验证不能写成通过。
- 异步和响应式更新不能伪装成同步栈；后端、SDK 或不可见历史写清证据停止点。
- 账号、i18n、异步或复用风险仅展开与改动有因果关系的项，规则从 SKILL.md 所链接的共享 references 读取。
- 不输出 endpoint、Token、Key、证书或生产配置；检查文件未覆盖旧内容，链接/行号/SHA 可核验。

最终回复提供绝对可点击文件路径、范围和影响结论的未验证项。文档已含完整解释时不再复制全文到聊天。
