# Git 因果取证

目标是证明行为因果，不是找最后修改某行的人。

| 角色 | 定义 |
|---|---|
| 缺陷引入 | 首次破坏业务不变量或漏掉必要保护 |
| 问题暴露 | 让潜伏问题可达、扩大触发或让症状可见 |
| 修复 | 恢复同一不变量并阻断错误链 |
| 防线缺失 | 应发现问题的约束、测试、检查、日志或清理缺口 |

一个提交可承担多种角色，证据与置信度分开写；最近提交、作者或首次报错时间不等于根因。

## 只读基线

范围优先级：用户 bad/good commit 或区间 → 目标 diff → 文件/symbol → 相关近期历史。记录 status、branch、short HEAD；用 `diff HEAD`、`diff`、`diff --cached` 区分组合/unstaged/staged，无关 hunk 不纳入。

- 修复未提交：写"当前工作区修复，尚无修复提交"；只有传播链、复现或测试证明 HEAD 含同一缺陷，才把 HEAD 当错误基线。最终 diff 不能证明已消失的中间态。
- 修复已提交：先 `show` 确认修复不变量，再查修复父版本；merge commit 先选对父提交，不在修复后的新行上 blame 根因。
- 业务仓库多分支频繁合并（dev_* / hotfix_*），注意 revert 与重复合并造成的同一改动多次出现。

## 搜索

```text
git log --follow -- <path>
git log -S "<exact-text>" -- <path>
git log -G "<regex>" -- <path>
git blame -w -M -C <pre-fix-rev> -L <start>,<end> -- <path>
git show <sha> -- <path>
git show <sha>^:<path>
```

`--follow` 只适合单文件重命名；`-S` 查文本数量变化，`-G` 查 diff 匹配；blame 只给线索，必须读提交与父版本。不得运行会切换工作树的 bisect。

## 因果确认

逐项回答：父版本是否满足不变量；改动破坏了哪种账号/i18n/身份/时序/清理边界；错误能否沿真实入口到达症状；是否只是搬移；后续改动是否才使其暴露；修复是否恢复同一不变量；测试/复现/日志支持哪个角色。

| 置信度 | 条件 |
|---|---|
| 已确认 | 父子差异、真实传播链与历史复现/修复前失败测试闭环 |
| 高度可能 | diff、传播链与修复闭环清晰，但未运行历史版本 |
| 候选 | 主要来自 blame、`-S/-G` 或提交信息，尚未证明可达 |
| 无法确定 | 历史、父版本、范围或中间态不可见 |

用户确认"现在修好"只支持修复角色。squash/rebase、生成代码、外部后端/SDK 或测试后补等情况说明证据边界，不推断不可见原因。
